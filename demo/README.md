# 스터디룸 발표 데모

`python3 demo/run.py`로 빌드하고 C 서버, 모의 LLM 세 대와 관측 서버를 실행한다. 기본 주소는 http://127.0.0.1:8080/ 이다. 다른 포트는 `--port 8081`, 비교 정책은 `--picker rr` 또는 `--picker hash`, 스레드 풀은 `--engine pool`을 사용한다. 실행 환경은 Python 3과 저장소의 C 빌드 도구다.

## 시연 순서

1. 민지로 제안 질문을 보내고, 답변이 끝나면 같은 학생으로 후속 질문을 보낸다. 두 요청의 배정 서버, 첫 토큰 시간과 재사용한 prefix 토큰 수를 확인한다.
2. 학생을 추가하거나 바꿔 질문을 이어 간다. 입력 옆에서 **스터디 전체**를 선택하면 응답을 기다리는 학생을 제외한 학생들이 동시에 질문을 보낸다. 서버별 활성 요청 수와 연결선이 바뀐다.
3. 마지막 답변을 완료한 뒤 운영 터미널에서 그 학생이 배정됐던 서버 번호 `1`, `2`, `3` 중 하나를 입력한다. 같은 학생의 다음 질문에서 실패한 시도와 다른 서버로의 배정을 확인한다. 같은 번호를 입력해 백엔드를 다시 띄우고, 제외 시간이 지난 뒤 후속 질문을 보내 복구를 확인한다.

이 시연은 실패 1회에서 해당 서버를 2.5초 동안 제외하고, 복구 시험 요청 한 건이 성공하면 정상 상태로 돌아오는 설정을 사용한다. 전송이 진행된 요청의 스트림이 백엔드 중단으로 끊긴 경우 결과에 해당 사실을 표시한다. 운영 터미널의 Ctrl+C로 서버를 종료한다.

## 관측값

- C 서버가 정적 화면을 서빙하고 학생의 HTTP 요청을 모의 LLM으로 전달한다. 학생의 대화는 브라우저 메모리에 보관한다.
- 정책, 후보, 후보별 활성 요청, 선택 시간과 실패는 C 서버에서 읽는다. 연결선은 연결 예약과 실제 응답 백엔드를 따른다. 서버의 활성 요청 수는 C 서버가 예약하고 아직 반납하지 않은 업스트림 요청 수다.
- 각 대화는 800토큰 분량의 공통 학습 자료를 가정한다. 캐시 HIT/MISS, 재사용 토큰 수와 모의 입력 처리 시간은 모의 LLM의 마지막 스트림 이벤트에서 읽는다. 첫 토큰 시간과 전체 응답 시간은 브라우저 시계로 측정한다. 학습 답변 예문은 화면에서 보여준다.
- 시연 관측은 별도 루프백 UDP 수집기에서만 활성화한다. 전송은 비블로킹이며 수집기에 전달되지 않은 기록은 UI에서 비어 있을 수 있다.

## 검증

`python3 demo/test_demo.py`가 같은 서버에 같은 길이의 입력을 보내 HIT·MISS의 입력 처리 시간을 비교한다. 겹치는 요청의 배정, 실제 프로세스 중단 시 재배정, 재기동 후 복구와 관측 로그도 확인한다.
