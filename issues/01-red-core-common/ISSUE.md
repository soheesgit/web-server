# [RED] core + common 기반 구현

## 목적

아키텍처 그림의 주황/빨강 공용 영역과 그림 아래쪽의 공용 기반 `core/`를 구현한다. 요청·응답 양쪽이 공유하는 HTTP 바이트 규칙을 한 번만 구현하고, 서버 전체에서 사용하는 문자열·버퍼·설정·로그·플랫폼 함수를 완성한다.

## 범위

- `src/core/`: `str`, `buf`, `config`, `log`, `platform`
- `src/common/`: HTTP 공용 타입, 헤더 처리, 본문 framing, keep-alive, 상태 문구·오류 본문
- 각 디렉토리 `README.md`의 구현 단계 갱신
- 정해진 테스트 ID만 완료 처리하고 `tests/pending.txt`에서 제거

`core/`는 PNG에서 별도 색으로 칠해지지 않은 기반 영역이므로, 팀 메모의 1단계 `core + common` 범위에 맞춰 이 이슈에 포함한다.

## 작업 항목

- [ ] `core/`의 TODO 스텁을 헤더 계약에 맞게 구현한다.
- [ ] `common/`은 README에서 완료로 표시되어 있으므로 재구현하지 않고, pending 계약 테스트로 동작을 확인한 뒤 실패하는 갭만 보완한다.
- [ ] 버퍼 상한, 실패 시 원상태 유지, 문자열 뷰 수명과 소유권 규칙을 확인한다.
- [ ] HTTP 헤더·본문 길이·chunked 경계·keep-alive 규칙을 기존 명세와 계약 테스트에 맞춘다.
- [ ] 플랫폼별 분기는 `core/platform.c`에 한정하고, 금지된 라이브러리·함수를 사용하지 않는다.
- [ ] 필요한 기능 테스트를 추가하되 기존 테스트 기대값이나 ID를 완화하지 않는다.
- [ ] 디렉토리 README의 구현 상태를 실제 완료 범위에 맞게 고친다.

## 완료 조건

- [ ] `U-CORE-*` 및 `U-COM-*` 대상 계약 테스트가 통과한다.
- [ ] 관련 설정 기능 테스트 `E-CF-02`, `E-CF-04`와 common이 맡는 E2E 경로가 통과한다.
- [ ] `make lint`, `make test`, Linux의 `make asan` 결과를 PR에 기록한다.
- [ ] 구현한 테스트 ID만 `tests/pending.txt`에서 제거한다.
- [ ] 공개 헤더 계약 변경이 필요하면 구현에 섞지 않고 `docs/DECISIONS.md` 제안과 별도 인터페이스 PR 절차를 따른다.
